# Digital Insight AI 🚀

**Digital Insight AI** هو منتج عربي عملي لاكتشاف ومقارنة أدوات الذكاء الاصطناعي ونشر الأدلة والمراجعات التي تساعد المستخدم على اتخاذ قرار أفضل قبل الاشتراك.

## مصدر الحقيقة الجديد

الموقع العام الجديد موجود داخل:

`site/`

هذه الطبقة **ثابتة ومستقلة عن Railway وWordPress وMariaDB وMongoDB**. لا تحتاج قاعدة بيانات أو خادم تطبيق لكي تعمل الصفحات العامة.

- الدومين النهائي: https://digitalinsightai.com/
- دليل الأدوات: https://digitalinsightai.com/tools/
- الاستضافة الإنتاجية المستهدفة: GitHub Pages عبر GitHub Actions
- Railway: طبقة rollback مؤقتة فقط أثناء قطع DNS، وليست اعتمادًا إنتاجيًا للموقع العام

التفاصيل التشغيلية: `PRODUCTION-ARCHITECTURE.md`.

## لماذا تغيرت البنية؟

سبب التغيير هو إزالة الاعتماد التشغيلي على خدمة مدفوعة وقاعدة بيانات لتقديم محتوى عام يمكن تقديمه كملفات ثابتة. النتيجة المطلوبة:

- تكلفة تشغيل الموقع العام تقترب من الصفر.
- لا توجد عملية PHP أو قاعدة بيانات يمكن أن تنام أو تتوقف.
- نشر أسرع وأقل تعقيدًا.
- سطح هجوم أصغر.
- قابلية نقل الاستضافة بدون إعادة كتابة المنتج.

## محتوى النسخة الجديدة

- الصفحة الرئيسية.
- دليل أدوات AI.
- المراجعات.
- الأدلة.
- صفحة المنهجية والإفصاح.
- سياسة الخصوصية.
- robots.txt و sitemap.xml.
- security headers وتحويلات للروابط القديمة.
- روابط تسويق بالعمولة مع إفصاح واضح.

## قواعد التنفيذ

1. `site/` هو مصدر الموقع العام الجديد.
2. لا تضف اعتمادًا على Railway أو قاعدة بيانات إلى `site/`.
3. لا تنقل DNS إلى GitHub Pages قبل نجاح artifact من `site/` والفحوص.
4. لا تحذف خدمات Railway أو أحجام البيانات قبل نجاح القطع ووجود مسار رجوع.
5. لا ترفع أسرارًا أو مفاتيح API إلى GitHub.
6. أي تغيير عام يجب أن يجتاز GitHub Actions ويحافظ على SEO والوصولية وتجربة الهاتف.

## الجودة

المسارات الأساسية:

- **Static Rebuild Check**: يتحقق من ملفات `site/` والروابط وعدم وجود اقتران ببنية خادم مدفوعة.
- **Static Site Quality Gate**: فحوص المستودع العامة والمواد الحساسة.
- **Agent Governance Verification**: بوابة الحوكمة الحالية.
- **Pages Production Deploy**: ينشر `site/` مباشرة إلى GitHub Pages عبر Actions.

## خطة القطع

1. بناء واختبار `site/`.
2. نشره عبر GitHub Pages Actions.
3. اختبار رابط Pages والمسارات والموبايل وSEO.
4. تفعيل `digitalinsightai.com` في إعدادات GitHub Pages.
5. نقل DNS مرة واحدة إلى GitHub Pages بعد التحقق.
6. التحقق من HTTPS و sitemap والروابط.
7. إبقاء Railway كمسار رجوع مؤقت.
8. إيقاف الموارد المدفوعة فقط بعد استقرار الموقع الجديد.

## الهدف التجاري

المشروع لا يفترض ربحًا مضمونًا. الهدف هو أصل رقمي موثوق عبر محتوى أصلي، مراجعات عملية، SEO، وتسويق بالعمولة بشفافية.

## الإفصاح

قد تحتوي بعض الصفحات على روابط تسويق بالعمولة. قد نحصل على عمولة عند الشراء دون تكلفة إضافية على المستخدم. وجود العمولة لا يجعل الأداة تلقائيًا أفضل.
