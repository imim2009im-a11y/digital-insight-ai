## تحويل التعلم إلى عمل

1. احفظ الرابط الأصلي وتاريخه، وحدد ادعاءً قابلًا للاختبار.
2. اختر مشكلة في مشروع قائم؛ لا تُنشئ مشروعًا مكررًا بسبب أداة جديدة.
3. حدد فرضية وقياسًا: خطأ قابل لإعادة الإنتاج، زمن تحميل، أو إتمام مهمة.
4. نفّذ تجربة محدودة وسجل الاختبار والقيود والتكلفة؛ لا تنسخ المحتوى أو التصميم.
5. راجع النتيجة قبل النشر أو الدمج. لا تحول metadata_only_unverified إلى خبر مؤكد.

## التنفيذ والقيود

أضيفت Fireship وNet Ninja وAhrefs إلى قائمة اكتشاف القنوات. معرّفات API الدائمة لم تُحسم بعد. صُحح تاريخ النشر إلى contentDetails.videoPublishedAt، وحُفظ channel_id القادم من API وأضيف وقت الجمع. حدود جمع خارج 1–50 تُرفض قبل الاتصال.

اختبارات الوحدة تستخدم بيانات مصطنعة ولا تُعد جمعًا حيًا أو مراجعة فيديو. التشغيل الحي يحتاج YOUTUBE_API_KEY صالحًا ووصولًا شبكيًا؛ لم يُقرأ أو يُنشأ مفتاح هنا. السجل التاريخي يُقرأ فقط ولا يُكتب تلقائيًا؛ الاستمرارية والجدولة لم تُنجزا بعد.

وثائق البنية الحالية تصف مرحلة نقل قديمة إلى Pages؛ يلزم توثيق البنية الحية قبل تعديل الإنتاج. هذا التغيير داخلي على فرع feat/youtube-source-intelligence-85 ولا يغير الموقع أو DNS أو الدفع أو الأسرار.
